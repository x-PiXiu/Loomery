# 06 · UI 设计：主窗口 V2（三列布局，现行）

> **V2（现行，2026-10-25 用户定稿方向）**：去掉活动栏，主窗口为**三列布局**——左（任务/项目侧栏，双模式）· 中（对话，主舞台）· 右（编辑器）。两列间分隔条可拖拽调宽并持久化；**中右可互换位置**（互换即原 IDE 形态，不再单设 IDE 预设页）。实现为自绘三列 flex + 分隔条，不再使用 dockview（决策记录见 10-adr.md ADR-0017）。
> 左栏规格：顶部 `＋新建任务 Ctrl+N` 与 `插件市场（P2 入口）`；任务列表支持搜索；**项目行**（📁 名称 + 查看文件☰ / 新建＋ / 更多⋯=编辑·删除·置顶）下挂该项目任务（相对时间，●进行中/⭐置顶）；点「查看文件」左栏切到**模式B 项目文件树**（顶部返回任务），点文件在右列打开；底部账户区。数据映射：项目=工作区，任务=Thread。
> 布局草图：docs/mockups/loomery-main-window-v2.drawio（V1 的 Codex/IDE 双布局预设与五槽位方案见下文存档章节与 mockups v1 文件）。

# 以下为 V1 存档（Codex 双布局预设，已被 V2 取代）

## 1. 结论【规范·V1存档】

**采用 Codex 风格 chat-first 布局作为默认预设，同时保留经典 IDE 布局预设。** 二者基于**同一套五个槽位**（活动栏/侧栏/编辑区/辅助区/状态栏）与 dockview 布局序列化实现：

- 布局预设 = dockview 序列化 JSON，随应用内置两份（`codex.json` / `ide.json`）；
- 用户手动拖拽后按当前预设持久化到 `userData/layout/<preset>.json`；
- 切换预设 = 放弃当前自定义布局并应用预设 JSON【建议，可改为提示保存】；
- 插件视图（P2）参与两种预设的停靠与持久化，无特殊通道。

Codex 三要素的映射：

| Codex 要素 | 映射到 |
|---|---|
| 左侧会话列表（Threads） | 侧栏 ThreadList |
| 对话即主界面 | Chat 面板为主区核心（`codex` 预设中占据最大面积） |
| diff 审查卡 | Chat 内审批卡（内联 diff）+ 点击展开到编辑区 Monaco DiffEditor 标签页 |

## 2. `codex` 预设（默认）【规范】

```
┌────┬──────────────────┬────────────────────────────────────────────┐
│活动│ 侧栏               │  主区                                       │
│栏  │ ┌──────────────┐ │  ┌────────────────────────────────────────┐│
│◆对话│ │ ThreadList    │ │  │ 编辑区（可折叠）                          ││
│◇文件│ │  今天 / 昨天   │ │  │  代码标签页 / Diff 标签页                 ││
│◇插件│ │  自动标题+摘要 │ │  └────────────────────────────────────────┘│
│    │ │  搜索          │ │  ┌────────────────────────────────────────┐│
│    │ └──────────────┘ │  │ Chat 面板（主舞台，占比最大）               ││
│    │                  │  │  · 消息流（markdown 流式）                 ││
│    │                  │  │  · 工具卡片（可折叠，状态自描述）            ││
│    │                  │  │  · 审批卡（内联 diff + Accept/Reject）     ││
│    │                  │  │  · Turn 页脚（token/费用/耗时）            ││
│    │                  │  │  · composer：模式/模型/@引用/发送⏸停止      ││
│    │                  │  └────────────────────────────────────────┘│
├────┴──────────────────┴────────────────────────────────────────────┤
│ 状态栏：模式 · 模型 · token/预算 · 挂起审批数 · checkpoint 可回滚      │
└────────────────────────────────────────────────────────────────────┘
```

- Chat 面板宽度默认 60%，编辑区默认折叠为窄条；点击 diff 卡/文件引用时编辑区展开。
- "对话聚焦模式"：双击 Chat 标签或快捷键 → Chat 独占主区（dockview group 最大化）。

## 4. 组件清单【规范】

所有组件为谦卑对象：输入 = 视图模型（由事件 reducer 归约），输出 = 用户意图（发 RPC 命令）。禁止在组件内做业务判断。

### 4.1 ThreadList（侧栏）

- 数据来源：session 的 Thread 元数据 + 事件重放出的摘要；
- 功能：时间分组（今天/昨天/更早）、自动标题（首条消息生成，可重命名）、搜索、新建会话、置顶（P2）；
- 选中 Thread → 切换 Chat 面板内容（本地切换，不查内核）。

### 4.2 Chat 面板

| 区块 | 行为 |
|---|---|
| 消息流 | `textDelta` 节流合并渲染 markdown；`reasoningDelta` 折叠区 |
| 工具卡片 | 状态机：pending → approval-needed / running → done / failed；默认折叠，approval-needed / failed 时自动展开；显示耗时与 token |
| 审批卡 | 内联 diff 预览（前 N hunk）+ Accept / Reject 按钮；Accept=`Ctrl/Cmd+Enter`，Reject=`Esc`；Reject 可附原因 |
| Diff 卡 | 已决提案的历史记录；点击 → 编辑区打开 Monaco DiffEditor 标签页（inline/side 可切换） |
| Checkpoint 横幅 | "本轮已修改 N 个文件 · 回滚"（`checkpointCreated` 驱动） |
| Turn 页脚 | token、费用估算、耗时、步数、终止原因（degraded/failed 时高亮展示 finalSummary） |
| composer | 模式切换（plan/edit/explain 分段控件）、模型选择、`@文件` 引用（补全文件路径）、Enter 发送 / Shift+Enter 换行、运行中变为"停止"按钮 |

### 4.3 编辑区

- Monaco 编辑器标签页 + DiffEditor 标签页（inline/side 切换）；
- dirty 标记与保存（Ctrl+S）；
- 编辑器事件 → `EnvironmentEvent`。

### 4.4 状态栏

模式（可点击切换）· 模型 · token/预算（80% 预警变色）· 挂起审批数（点击跳转审批卡）· checkpoint 状态 · 事件时间线入口（开发模式常显）。

### 4.5 调试时间线（开发模式）

全部事件的时间线视图：按 seq 排列，支持按 type 过滤、按 turn 分组、查看 payload JSON——排障主工具，P1 必备。

### 4.6 设置视图【规范】

入口：状态栏齿轮 / 命令面板。基础版承载 `AppConfig`（03 §11）：模型配置（provider/modelId/baseURL/密钥引用——密钥本体写入 OS keychain）、审批策略表、会话恢复策略、限额（步数/token/墙钟/截断上限）、护栏模式表、工作区根列表。企业策略层（09 §3）在此视图中只读呈现。M3 交付基础版。

## 5. 关键交互流【规范】

1. **审批**：`approvalRequired` → 审批卡展开 + 状态栏计数 +1（可配系统通知）；决策经 RPC 回传 `ApprovalRequester`；超时不存在（挂起不限时），仅会话关闭置 expired。
2. **停止**：运行中点击停止 / `Esc` → `turnCancelled` → abort 传播（07 §6）→ 流中断、执行中工具终止、消息流收尾。
3. **回滚**：Checkpoint 横幅"回滚" → 确认对话框（列出将被还原的文件）→ `checkpointRestored` → 编辑器重新加载被还原文件。
4. **切换模式**：composer 分段控件 → RPC → `modeChanged`；plan/explain 下 composer 显示"只读模式"徽标。
5. **恢复会话**：启动重放（05 §17.3）→ ThreadList 恢复列表 → 最近 Thread 的 Chat 内容按事件重放渲染（delta 合并后的最终态）。

## 6. 视觉基调【参考】

深色主题默认（浅色可后置）、低 chrome（细边框、少图标）、卡片圆角、等宽字体用于代码与 diff、事件驱动的状态徽标（色点 + 文案）。视觉细节后续按设计系统细化，不影响本文件的布局与交互规范。
