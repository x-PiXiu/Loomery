# 09 · 企业化预留设计

> 本文件为**预留**设计：P1/P2/P3 不实现，但架构必须为其留好落点。核心判断：下列需求绝大多数能被"事件=记录、策略=数据、能力=端口"三条既有原则自然接住，不需要新增架构层。

## 1. 数据流向治理【架构级】

| 需求 | 落点 |
|---|---|
| 模型供应商白名单 / 私有 LLM 网关 / 本地模型 | `ModelClient` 端口（新增适配器即可）；配置中供应商列表约束 |
| 工具结果出网脱敏（密钥/内网地址进 prompt 前过滤） | tool-runtime 管道新增一个脱敏步骤（护栏链位置），规则为配置数据 |
| 密钥集中管理 / 企业凭据代理 | shell 密钥通道（07 §3）扩展为企业代理实现 |

## 2. 审计流【架构级】

- 落点：`EventSink` 的第二个消费者（审计存储，只追加）。
- 前提：04 A3 工具链事件完整——toolRequested/approvalResolved/toolExecuted/observationAdded 已覆盖"谁在何时让 Agent 动了什么"。
- 交付形态：审计 JSONL 按日滚动 + 导出接口。

## 3. 策略下发与治理【架构级】

| 需求 | 落点 |
|---|---|
| 组织级强制 ask / 工具黑名单 / 只读锁定 / 模型白名单 | 审批策略表与护栏规则表数据化（07 §1/§4 已是配置数据），增加"企业策略层叠加（只允许改严）"合并逻辑 |
| 项目级 `.agentrc` | 策略配置的三级合并：默认 < 项目 < 企业 < 用户覆盖？【规范：企业层优先于一切，顺序待 ADR】 |

## 4. 成本治理【架构级】

- budget 模块预留"配额查询端口"：单 Turn 预算之上叠加个人/团队配额源（本地配置或远端服务）。
- 用量聚合（session）已按 Step/Turn/Thread 维度记录，报表是消费问题不是采集问题。

## 5. Agent 质量工程（evals）【架构级】

企业会问"你怎么证明升级 prompt 没把 Agent 弄坏"。P2 回放测试已是雏形，预留扩展：

1. 基准任务集（黄金仓库 + 期望工具调用序列）；
2. 指标：工具调用成功率、任务完成率、平均步数、token 成本；
3. 回放评测进 CI：prompt/模型变更触发基线对比。

## 6. 团队协作【产品级】

- 会话导出/分享/重放：JSONL 事件日志天然可携（P2 回放能力复用）。
- 团队记忆库：长期记忆从个人扩展到共享库（带审核流）——`MemoryStore` 端口多一个实现位。

## 7. 交付运维【产品级，不动架构】

Windows Authenticode 签名、静默部署（MSI）、electron-updater 自动更新、内网离线运行、崩溃上报与诊断包导出、结构化日志（分级/脱敏/轮转）。

## 8. 身份与归属【产品级】

- Agent 操作以用户身份归属（git commit author、审计主体）。
- 云侧功能（团队配置同步、记忆共享）接企业 SSO；本地版仅需本地档案。

## 9. 插件生态治理（P2 企业版）

插件签名验证、企业白名单、插件权限审计——manifest 已预留 `publisher/signature` 字段。

## 10. 可观测性【产品级】

OpenTelemetry trace（一个 Turn = 一棵 span 树，span 对应 Step 与工具执行）、审批拒绝率看板（prompt 质量信号）、模型错误率监控。
